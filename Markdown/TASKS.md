# TASKS

## 구현 원칙

### 작업 전 확인 사항

* 기존 구현을 먼저 분석하고 재사용 가능한 구조를 우선 활용한다.
* 동일한 기능이 이미 존재한다면 새로운 시스템을 만들지 않고 기존 시스템을 확장한다.
* 필요 이상의 리팩토링은 지양한다.
* 현재 정상적으로 동작하는 기능은 변경하지 않는다.
* 새로운 Manager나 시스템은 반드시 필요한 경우에만 추가한다.
* 구현 완료 후에는 기존 기능이 정상적으로 동작하는지 확인한다.

---

# 구현 항목

## 1. Enemy Queue UI 슬롯 칸 안에 Enemy 행동 스프라이트 표시

### 목표

Enemy Queue UI 슬롯이 채워질 때 (앞선 4박에서) 행동 차례대로, 행동에 대한 스프라이트를 표시

### 구현 방식

* 
* 기존 Flip 1회의 시간을 절반으로 나누어 Flip을 2회 수행한다.
* 기존 Sprite 전환 시스템을 최대한 활용한다.

---

## 2. Hit Animation

### 목표

피격 시 타격감을 표현한다.

### 포함 요소

* Damage Flash (빨간색)
* 캐릭터의 짧은 흔들림(Shake)

### 구현 방식

* 기존 피격 처리 흐름과 자연스럽게 연동한다.
* 애니메이션이 끝난 뒤 원래 상태로 복귀한다.

---

## 3. Enemy Queue UI 변경

### 목표

기존 박자 행동 UI를 슬롯 기반 UI로 변경한다.

### 요구 사항

* 화면 중앙 상단에 표시한다.
* 행동 슬롯은 총 4칸이다.
* 적의 행동이 공개될 때마다 해당 슬롯이 순서대로 채워진다.
* 페이즈 종료 시 슬롯 내용을 모두 초기화한다.
* Enemy Queue UI는 항상 화면에 표시된다.

---

## 4. Player Queue UI

### 목표

기존 박자 입력 UI를 슬롯 기반 UI로 변경한다.

### 요구 사항

* Enemy Queue 바로 아래에 배치한다.
* 입력 슬롯은 총 4칸이다.
* 플레이어가 박자마다 입력한 행동을 순서대로 표시한다.
* 페이즈 종료 시 슬롯 내용을 모두 초기화한다.
* Player Queue UI는 항상 화면에 표시된다.

### 슬롯 연출

각 박자가 시작될 때 다음 순서의 슬롯이 아래 순서대로 연출된다.

1. 슬롯이 투명한 상태에서 시작
2. 박자가 들어오는 순간 불투명해지며 깜빡임
3. 플레이어 입력 대기
4. 입력 완료 후 입력한 행동 아이콘 표시

### 슬롯 색상

판정 결과에 따라 슬롯 색상을 변경한다.

* 플레이어가 피해를 입은 경우 → 빨간색
* 적에게 피해를 준 경우 → 초록색
* 둘 다 피해를 입었거나 아무도 피해를 입지 않은 경우 → 흰색

## 5. Score 시스템

### 목표

점수 계산 시스템을 구현한다.

### 요구 사항

* 적을 빠르게 처치할수록 높은 점수를 획득한다.
* 강한 적일수록 추가 점수를 획득한다.
* 향후 점수 계산식을 쉽게 수정할 수 있도록 구현한다.

---

## 6. Enemy Queue 진행 방식 변경

### 목표

현재는 **적의 행동을 공개하는 4박** 동안 적 캐릭터의 스프라이트도 함께 변경되고 있다.

이를 변경하여 **적의 행동 공개 단계에서는 Enemy Queue UI만 갱신**하고, **적 캐릭터의 실제 스프라이트는 플레이어 입력 단계에서만 변경**되도록 수정한다.

---

### 동작 흐름

#### Enemy Reveal (Phase에서 앞선 4박)

* 적의 실제 스프라이트는 변경하지 않는다.
* Enemy Queue UI의 슬롯만 박자에 맞춰 순서대로 채운다.
* 이 단계에서는 적 캐릭터는 Idle 상태를 유지한다.

#### Player Input (Phase에서 뒤의 4박)

* 플레이어가 입력하는 4박에 맞춰 적의 실제 스프라이트를 순서대로 변경한다.
* Enemy Queue에 저장된 행동을 순서대로 꺼내어 Flip 전환 애니메이션과 함께 표시한다.
* 적의 스프라이트 변경은 **플레이어의 입력 성공 여부와 관계없이** 박자 타이밍에 맞춰 자동으로 진행된다.
* 즉, 플레이어가 버튼을 누르는 순간이 아니라 **Beat 이벤트가 발생하는 시점**에 적의 스프라이트가 변경되어야 한다.

---

### 구현 시 주의사항

* Enemy Queue UI의 동작 방식은 유지한다.
* 적의 행동 데이터 생성 및 Queue 관리 방식은 변경하지 않는다.
* 변경되는 것은 **적 캐릭터 스프라이트가 표시되는 시점**뿐이다.
* 기존 Beat 시스템을 최대한 재사용하여 구현한다.


## 7. Effect 시스템

### 목표

전투 연출을 위한 이펙트를 추가한다.

### 포함 요소

* 공격 이펙트
* 방어 이펙트
* UI 이펙트
* 기타 연출 효과

### 구현 방식

* 기존 전투 흐름과 자연스럽게 연결한다.
* 새로운 연출을 쉽게 추가할 수 있도록 확장성을 고려한다.

---

## 8. Camera Shake

### 목표

타격감을 강화하기 위한 카메라 흔들림을 추가한다.

### 요구 사항

* 공격 적중 시 Shake를 재생한다.
* 강한 공격은 더 강한 Shake를 사용할 수 있도록 구현한다.
* 향후 Effect 시스템과 연동 가능하도록 구현한다.
