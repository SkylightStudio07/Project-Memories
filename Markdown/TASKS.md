# TASKS

## 구현 원칙

### 작업 전 확인 사항

* 기존 구현을 먼저 분석하고 재사용 가능한 구조를 우선 활용한다.
* 동일한 기능이 이미 존재한다면 새로운 시스템을 만들지 않고 기존 시스템을 확장한다.
* 필요 이상의 리팩토링은 지양한다.
* 현재 정상적으로 동작하는 기능은 변경하지 않는다.
* 새로운 Manager나 시스템은 반드시 필요한 경우에만 추가한다.
* 구현 완료 후 기존 기능이 정상적으로 동작하는지 확인한다.

# 구현 항목

## 1. Queue UI 통합 및 개선

### 목표

기존의 **Enemy Queue UI**와 **Player Queue UI**를 하나의 Queue UI로 통합한다.

플레이어가 어떤 키를 입력했는지는 표시하지 않고, **각 박자의 전투 결과(성공/실패)** 만 슬롯에 표현한다.

또한 플레이어 입력 단계에서는 각 박자의 입력 제한 시간을 시각적으로 표시한다.

### 요구 사항

#### Queue UI

* Enemy Queue UI를 기반으로 사용한다.
* 기존 Player Queue UI는 제거한다.
* 플레이어의 입력 아이콘은 표시하지 않는다.
* 각 슬롯은 판정 결과에 따라 색상을 변경한다.

  * 플레이어가 피해를 입은 경우 → **빨간색**
  * 적에게 피해를 준 경우 → **초록색**
  * 그 외(무효, 상쇄 등) → **흰색**

#### Player Beat Cursor

플레이어 입력 단계(후반 4박)에서는 현재 입력해야 하는 슬롯 위에 Beat Cursor를 표시한다.

* 입력 가능 시간이 시작되면 Cursor가 표시된다.
* 판정 제한 시간이 흐를수록 시계 방향으로 채워진다.
* Cursor가 모두 채워지는 순간 해당 박자의 입력 시간이 종료된다.
* 다음 박자가 시작되면 다음 슬롯으로 이동한다.

## 1.5. 적 행동 타이밍 변경

### 목표

현재는 적이 **Beat 타이밍에 맞춰 자동으로 행동**하고, 플레이어의 입력은 그와 별개로 처리되고 있다.

이를 변경하여 **플레이어의 입력 판정과 적의 행동이 동일한 시점에 발생하도록 수정**한다.

즉, 플레이어가 입력에 성공하면 해당 입력과 동시에 적의 행동 스프라이트가 전환되고 전투 판정도 함께 이루어진다.

---

### 동작 방식

#### 플레이어가 입력 시간 내에 입력한 경우

* 플레이어가 입력하는 순간 적의 행동 스프라이트를 Flip 애니메이션과 함께 전환한다.
* 같은 시점에 전투 판정을 수행한다.
* 판정이 끝나면 다음 Beat를 기다린다.

#### 플레이어가 입력하지 못한 경우

* 입력 제한 시간이 끝나는 즉시 적이 자동으로 행동한다.
* 적의 행동 스프라이트를 전환한다.
* 같은 시점에 플레이어의 입력 실패(Miss) 판정을 수행한다.
* 추가 대기 시간 없이 즉시 다음 Beat로 진행한다.

---

### 입력 판정 시간

입력 가능 시간은 실제 Beat 전체와 동일하지 않다.

입력 판정 구간은 Beat의 시작과 끝에 일정한 Offset을 두어 구성한다.

예시

```
Beat 시작
│
├─ 입력 불가 (Start Offset)
│
├─ 입력 가능
│
├─ 입력 가능
│
├─ 입력 가능
│
├─ 입력 불가 (End Offset)
│
Beat 종료 → 적 자동 행동(Miss인 경우)
```

---

### 구현 목적

다음 문제를 방지한다.

* Beat 종료 시 적의 행동과 다음 Beat 시작이 겹치는 현상
* 늦은 입력이 다음 Beat의 입력으로 처리되는 현상
* 한 번의 실수로 두 개의 Beat를 동시에 실패하는 상황

입력은 반드시 현재 Beat의 판정 구간 안에서만 인정되어야 하며, 판정 구간이 종료되면 즉시 다음 Beat로 넘어갈 준비를 한다.

또한 이전 박자를 패스 당한 경우, 일정 시간동안은 입력을 받지 않게 해 플레이어가 박자를 놓쳤을 때 다음 박자로 입력되어버리는 문제를 막는다.

---

### 구현 시 주의사항

* 기존 Beat 시스템을 최대한 재사용한다.
* Beat의 길이는 변경하지 않는다.
* 변경되는 것은 **입력 판정이 이루어지는 시점과 적 행동이 발생하는 타이밍**이다.
* 입력 성공과 Miss 모두 동일한 흐름으로 처리하여 전투 진행이 항상 일정한 리듬을 유지하도록 구현한다.

## 2. 공격 및 피격 연출 개선

### 목표

공격 성공과 피격 연출을 명확하게 구분하여 시인성과 타격감을 향상시킨다.

### 요구 사항

#### 피격

* 피격 시에만 Camera Shake를 재생한다.
* 기존 피격 연출은 유지하면서 타격감을 강화한다.

#### 공격 성공

* Camera Shake는 사용하지 않는다.
* 적 캐릭터가 크게 흔들리도록 연출한다.
* Damage Flash를 기존보다 더욱 명확하게 표현한다.
* 공격 성공 여부가 직관적으로 느껴질 수 있도록 연출을 개선한다.

---

## 3. 기존 임시 행동 표시 제거

### 목표

행동 스프라이트가 없던 시절 사용했던 임시 연출을 제거한다.

### 요구 사항

* 캐릭터 색상을 깜빡여 행동을 표현하던 기존 코드를 제거한다.
* 현재의 Sprite 전환 애니메이션을 사용하도록 정리한다.
* 더 이상 사용되지 않는 관련 코드가 있다면 함께 제거한다.

## 4. Score HUD 구현

### 목표

기존 `OnScoreChanged` 이벤트를 활용하여 실제 점수 UI와 점수 획득 연출을 구현한다.

### 요구 사항

#### 기본 점수

* 적에게 피해를 줄 때마다 획득한 점수를 Floating Text로 표시한다.
* Floating Text는 점수 HUD 방향으로 이동한다.
* HUD에 도착하는 순간 실제 점수가 증가한다.

#### 처치 보너스

* 적 처치 시 추가 점수를 지급한다.
* 처치 시간이 짧을수록 높은 점수를 지급한다.
* 처치 보너스 역시 Floating Text로 표시한다.
* Floating Text는 Score HUD로 이동한다.
* HUD에 도착하는 순간 점수가 증가한다.

#### 연출

* 점수가 높을수록 Floating Text의 크기를 더 크게 표시한다.
* 점수 획득이 시원하게 느껴질 수 있도록 애니메이션을 적용한다.

---

## 5. DOTween을 활용한 애니메이션 폴리싱

### 목표

DOTween을 활용하여 UI와 전투 연출의 완성도를 높인다.

### 요구 사항

* Floating Score 애니메이션에 DOTween을 사용한다.
* Score HUD로 빨려 들어가는 연출에 DOTween을 사용한다.
* 기존 UI 및 전투 연출 중 자연스럽게 개선 가능한 부분에는 과하지 않은 수준으로 DOTween을 적용한다.
* 전체적인 게임의 타격감과 시각적 만족감을 향상시키는 것을 목표로 한다.
